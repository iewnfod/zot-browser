# 重构：双窗口架构 → 单窗口 + 双层 WebContentsView

## 目标
删除当前的双窗口（pageWindow + overlayWindow）架构，改为单一 `BaseWindow`（透明），UI 和网页各自作为 `WebContentsView` 加载。UI View 位于 z-order 最底层，网页 View 叠加在上层。由于网页 View 仅覆盖内容区域（pageRect），UI 的侧栏/导航栏区域始终可见。

## 架构对比

### 当前架构
```
[Overlay BrowserWindow - transparent, non-focusable]
  ↳ 加载 React UI，点击穿透 + 主进程轮询判断
[Page BrowserWindow - opaque]
  ↳ 承载 WebContentsView（网页），不加载 HTML
```

### 目标架构
```
[BaseWindow - transparent, single window]
  ↳ contentView
    ↳ WebContentsView（网页 tab3）   ← z-order top
    ↳ WebContentsView（网页 tab2）
    ↳ WebContentsView（网页 tab1）
    ↳ WebContentsView（UI - React）  ← z-order bottom, full window bounds
```

## 关键设计决策

1. **BaseWindow 而非 BrowserWindow**：按用户要求使用 `BaseWindow`（Electron 38 支持）。它更轻量、不加载自有 webContents。macOS 上失去原生 traffic light 按钮，改用已有的自定义窗口按钮（WebViewContainer 中已有非 macOS 的 min/max/close 按钮）。

2. **UI View z-order 保底机制**：在 `bringToFront()` 中，每次将网页 view 置顶后，立即对 UI view 调用 `mainWindow.contentView.addChildView(uiView)`，这会将其移回 index 0（最底层）。简单可靠。

3. **UI View 始终全窗口 bounds**：在 `relayout()` 中，UI view 的 bounds 始终为整个窗口大小，不随 pageRect 变化。

4. **背景透明链**：`BaseWindow(transparent:true)` → `UI WebContentsView`（html/body 透明，侧栏/导航栏不透明）→ `网页 WebContentsView`（网页内容不透明）。网页 view 叠在 UI view 的内容区域上方，透过 UI view 的透明背景可见；侧栏区域无网页 view 覆盖，UI 控件直接可见。

5. **鼠标事件自然路由**：不再需要点击穿透。鼠标事件由 Electron 自动路由到最上层的可见 WebContentsView。在侧栏区域，UI view 是最上层（无网页 view 覆盖），事件到达 UI。在内容区域，网页 view 在最上层，事件到达网页。模态框在 UI view 中渲染，打开时覆盖全窗口，事件自然到达 UI。
